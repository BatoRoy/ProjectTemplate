# Native client flavor: port plan (iced)

Decision (2026-11-14): the native flavor is **iced 0.14**. The proof of concept (`native/poc-iced`) matched
Electron's look and feel on desktop and touchscreen at about 1/3 of the memory and 3× faster startup. This plan takes
it from proof of concept to a template flavor that `new-app.sh` can choose, then to the full component kit.
The Electron flavor stays, unchanged.

Inputs, read before working on any step:
- `native/plan/COMPONENT-INVENTORY.md`: every component, hook and Showcase card; the shared infrastructure items
  (INF-1…18); batches; the hard components.
- `native/plan/INFRA-INVENTORY.md`: scaffolding, the Electron→native shell mapping, packaging, patched crates, CI,
  layout.
- `native/HYBRID-SPEC.md`: the pixel spec. `native/POC-BRIEF.md`: the off-screen testing rules (still binding).

## Decisions (user, 2026-11-14)

| Question | Decision |
|---|---|
| Shared repo `BatoRoy/bato-native` | **Public** on GitHub, no CI token needed |
| bato-hub | **Skipped**: the user no longer uses it; native apps are not added to it |
| Wayland file drop (desktop → app) | **Fixed in Phase 3**: a winit patch in batch B3 (FileDropzone) |

## Architecture

### Two repos

**`BatoRoy/bato-native`** (new, shared, tagged `vX.Y.Z`). Everything every native app has in common:

| Path | What |
|---|---|
| `crates/bato-theme` | Tokens, accents, settings (from `native/bato-theme`) |
| `crates/scroll-physics` | Wheel, touchpad, touch, autoscroll (from `native/scroll-physics`) |
| `crates/bato-kit` | The widget kit, re-exporting `iced`; extracted from poc-iced, grows through Phases 2–4 |
| `crates/bato-shell` | Window and identity, the HTTP client (ureq + system CA), portal dialogs, notifications, the bundled-server supervisor, the updater, `BATO_VIEW`/`BATO_SMOKE` |
| `patched/{winit,cosmic-text,cryoglyph,iced_wgpu}` | Normalised patched sources, regenerated by `scripts/regen-patched.sh` from `patches/` |
| `assets/` | Fonts and icons, compiled in |
| `examples/gallery` | The Showcase, the kit's visual test bench |
| `docs/` | Spec, reference shots, plan, PoCs archived |

**`bato-template`** gains `app-client-native/`, a thin app on `bato-kit` + `bato-shell` (Home, Examples = gallery
pages, App Options, About). `new-app.sh --native` keeps it and drops `app-client/`, and vice versa. `native/` leaves
the template, so nothing native leaks into Electron apps.

**Why a shared repo:** the template is fork-and-drift. A scroll, text or theme fix in a vendored kit would have to be
hand-ported into up to 30 apps. With a git tag, each app gets fixes with `make native-bump TAG=…` when it chooses to,
and the iced 0.15 port happens once. An app can still copy a kit module locally to diverge.

### Rules

- Apps use iced only through `bato_kit::iced`.
- Every app's `Cargo.toml` carries the 4-line `[patch.crates-io]` block (Cargo only honours it at the root), pinned to
  the same tag.
- Each patched crate exports `BATO_PATCH`, and the kit asserts it, so an unpatched build fails to compile instead of
  silently losing blur or hinting. Builds use `--locked`.
- FreeType is built `bundled`: the same rendering on every machine, and no system FreeType version requirement.
- **Bundled server:** none by default. A native app does local work in-process. `app-server/` stays for apps that need
  a real backend (daemon, deployed, multi-client). `bato-shell` has an optional sidecar supervisor (spawn on a free
  port, `BATO_BACKEND_URL`, kill on exit) for migrating the 7 apps that bundle a Go server today.
- **Updates:** a `desktop` release updates through `bato install <slug>`. The registry is checked on launch and every
  30 min; "Restart to update" relaunches. Without the bato CLI, the app shows the install command.

## Phases

Each phase ends at a **checkpoint the user tests by hand**. Agents work in git worktrees; the coordinator reviews, runs
the gates and merges. Nothing merges with failing tests, a fidelity regression or a non-idle idle.

### Phase 1: Foundation (mostly sequential, 2–3 agents)

Goal: `./new-app.sh Foo ../Foo --native` produces an app that builds from a clean clone, looks and scrolls exactly like
the PoC, publishes to bato as `type: "desktop"`, installs with `bato install`, and updates itself.

| Step | Work | Who |
|---|---|---|
| 1.1 | Create `bato-native`. Move the shared crates, assets, spec and PoCs in. Make `patched/` with the regen script, tripwires, bundled FreeType and the `x11` feature. Add its own CI (fmt, clippy, test). | coordinator + 1 agent |
| 1.2 | **F1 kit skeleton** (INF-1, 9, 11, 13–15, 17): extract the PoC widgets into `bato-kit` (`Surface`, `Label`, `Icon`, Scroller, Modal, Toast, RailTip, Switch, input) with a `Ctx` (what a widget sits on, for translucent colors), an opacity multiplier and animation helpers. Add all lucide icons, layout helpers, a date formatter and a key-value store. Promote the shared atoms (SegmentedControl, Checkbox, EmptyState, Spinner, Button loading). Gallery skeleton with an empty file per Showcase card. | 1 agent |
| 1.3 | **`bato-shell`**: settings, ureq HTTP with TLS, portal file dialogs (your FileChooser is BatoBrowse/KDE), notifications with click-to-focus, backend URL resolution, the supervisor, the updater, smoke/view hooks, window identity, decorations default. | 1 agent, parallel to 1.2 |
| 1.4 | **Template wiring**: `app-client-native/` on the kit; `new-app.sh --native` (stamp `brand.rs`, `[[bin]]`, `bato.json`); Makefile `HAS_NATIVE` dispatch (`client`, `dev-client`, `stage-native`, `publish-client -v $(VERSION)`, `native-bump`, lint/test); `build.rs` reads `VERSION`; `release-native.yml`; rust job in `test.yml`; README and `CLIENT.md`; remove `native/`. | 1 agent after 1.2/1.3 |
| 1.5 | **Fidelity harness**: `BATO_VIEW=view=examples&tab=<tab>&card=<card>` in the Electron and native clients; a `compare` tool that captures both off-screen and reports per-card pixel diff with a diff image. Electron reference shots for every Showcase card. | 1 agent, parallel |
| 1.6 | **Outside the template:** BatoGit `ship.go` learns `app-client-native/`; the bato skill docs (new-app, publish, bundling); register a test app's icon. | coordinator |

**Checkpoint 1:** scaffold a throwaway native app, publish it, `bato install` it on the desktop and laptop, update it.

### Phase 2: Interaction core (F2, 3 agents in parallel)

| Agent | Scope (inventory INF ids) |
|---|---|
| Overlay | Port `floating.ts` with flip/shift and tests; anchored overlay; dismissal; `MenuList`; overlay stack (modals, drawers, nested); hotkeys (INF-3, 4, 5, 6) |
| Focus | Focus system for custom widgets; Tab order; focus ring painter in `Surface`; dialog focus trap (INF-2) |
| Scroller + Field | General scroller (bounded, horizontal, nested, `scroll_to`, edge fade; reuses the PoC physics); `Field` and control style (INF-7, 10) |

**Checkpoint 2:** focus rings, Tab order and a menu/popover demo in the gallery.

### Phase 3: Component batches (up to 5 agents at a time)

Each batch owns its own kit files and gallery card files (inventory §3), so batches never touch the same file.
Each batch must deliver, per component:
- gallery cards;
- a pixel diff against the Electron card;
- unit tests;
- keyboard and touch behaviour;
- an idle check.

| Wave | Batches |
|---|---|
| 3a | B1 basic inputs · B2 anchored overlays and pickers · B3 modal family + command palette + file dropzone · B4 feedback and layout atoms · B5 date and time |
| 3b | B6 data and charts · B7 drag and drop (sortable, kanban, editor tabs) |
| long poles, start right after Phase 1 | B8 code editor (cosmic-text editor + syntect, vi mode) · B9 node graph (canvas, zoom-aware layout for crisp text) |

**Checkpoint 3:** the whole Examples page side by side with Electron.

### Phase 4: Finish

1. B10 Dashboard (needs B2, B6, B7).
2. B11 fidelity pass: every card diffed; hover-on-scroll, focus rings, perf with all tabs visited (memory, idle CPU,
   first frame).
3. Tag `bato-native v1.0.0`, and the template pins it.

**Checkpoint 4:** the native template is feature-complete; `new-app.sh` offers it alongside Electron.

### Phase 5: App migration (separate plan per app, after Phase 4)

1. **Pilot:** one small app without a bundled server, to shake out the migration recipe.
2. **The 7 bundled-server apps** (BatoBrowse, BatoDisplay, BatoEdit, BatoGit, BatoMod, BatoShare, BatoSound): native UI
   + the same Go server as a sidecar first. Moving the logic into Rust is a later, per-app call.
3. **Daemon/deployed-backend apps:** native UI against the existing server.
4. Apps where Electron fits better stay Electron.

## Known limitations to carry or fix

| Limitation | Plan |
|---|---|
| bato-hub only embeds web bundles, so native apps can't appear in it | Accepted: hub is not in use |
| Desktop → app file drag-and-drop doesn't work on Wayland (winit) | A 5th patch, in B3 |
| No accessibility (AccessKit) in iced 0.14 | Revisit with iced 0.15 |
| iced 0.15 redesigns the widget API | One kit port in bato-native when it ships; apps move by tag bump |
| No rotation transform | The Kanban drag tilt is dropped |
| Showcase reference shots need a React `BATO_VIEW` tab hook | Step 1.5 |
